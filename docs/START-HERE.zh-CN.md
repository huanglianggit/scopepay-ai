## 体验流程

1. 在项目下拉框中选择项目。Bloom Studio 留有已完成的模拟支付记录；Lumen portfolio 留有中文分析草稿。
2. 点击 **New request** 开始新的分析，或在 **Recent versions** 打开已有草稿。
3. 输入客户追加需求，点击 **Run walkthrough analysis**。当前为明确标注的规则演示模式。
4. 查看 **View source evidence**，修改分类和金额；修改分析分类时需要填写理由。对 **Needs clarification** 项填写澄清内容，也可以取消勾选将其排除。**Already included** 项不能收费。
5. 点击 **Save draft** 保存；点击 **Lock & share quote** 固定版本并生成客户链接。
6. 打开 **Open client review**，填写测试姓名、勾选确认后点击 **Accept this version**。当前可用 **Simulate demo payment** 体验模拟付款。
7. 返回工作台点 **Refresh** 查看状态；**Export record** 下载包含需求、确认和付款状态的记录包。

客户可选择 **Request a revision**。尚未接受或被拒绝的报价可 **Create revision**；旧版本会被标记为已替换。接受后的报价不能直接修改。

## 10月19日新增体验

- **报价版本对比**：修订时显示客户上一版反馈；保存后可查看增删项、分类、价格、澄清、交期和备注的前后变化。发布后的客户页也能看到对比。新版本指纹绑定上一版指纹和冻结的历史条款；历史旧报价保持原样，不追溯修改。
- **Scope & fees**：左侧新增项目范围/费用汇总。分别显示已约定金额、Sandbox测试付款、Sandbox未付款、模拟付款和演示未付款；不把未确认报价计入已约定金额，也不把模拟交易当作收入。
- **Export project summary**：导出项目确认范围、各变更交期、金额、付款环境及校验文件；与单个版本的 **Export record** 区分。
- 可选择新建的 **Northstar website - QA demo** 体验本轮测试记录：340美元报价修订为40美元并完成模拟付款；另有一份零元确认。原 Bloom 和 Lumen 数据保留。

零元变更也可发布和确认，确认后显示 **Confirmed · no payment**，不会要求支付或伪装成付款成功。同项目另一份报价被接受后，旧的未确认报价会被视为范围过期，不能继续接受；请重新分析或修订。范围过期的修订会重新分析，需再次检查金额和澄清内容。

工作台会显示客户姓名和反馈，导出文件也会记录回应、版本指纹、付款环境和时间线。Sandbox 模式新增 **Refresh payment status**；仅查询已完成支付，不会主动扣款。过期/作废订单可以重新发起测试结账，普通网络错误不会创建替代订单。

## 重新启动

在此项目目录执行：

```powershell
./start.ps1
```

如果提示端口已占用，通常表示预览仍在运行，先直接打开地址。完整安装步骤见上级 `README.md`。

## 真实接口接入

在项目目录把 `.env.example` 复制为 `.env`，通过编辑器填写配置。不要把密钥发到公开仓库。

- PayPal：登录 Developer 后台，在 **Sandbox → Apps & Credentials** 取得 `PAYPAL_CLIENT_ID` 和 `PAYPAL_CLIENT_SECRET`，填入 `.env`，重启服务。必须新建并发布一份报价，才会使用 Sandbox 付款；旧的模拟报价保持原模式。
- AI：配置可用的 OpenAI 兼容模型服务，或本地 Ollama。需要填写实际的模型名称、接口地址，以及服务需要的密钥。
- 页面 **Connections** 可查看配置状态，但“Configured”不代表已完成外部连通性验证；还需要实际分析和支付一次。
